# RO-FACTORY — цифровой двойник завода Allur

Веб-приложение для мониторинга производства: показатели завода, состояние участков, простои оборудования, качество, месячный план и рекомендации. Проект использует FastAPI, SQLite и интерфейс на HTML, CSS и JavaScript.

## Проделанная работа

### Интерфейс и оформление

- Переделан фронтенд по предоставленным макетам Figma: общий header, боковая навигация, центральные карточки и правая панель KPI.
- Выбрана палитра в автомобильном стиле: тёмно-синий `#001E50`, синий `#007BC1`, светлый фон `#EDF2F7`, белые карточки и графитовый текст.
- Подключён **Font Awesome Free 6.7.2 локально**. Иконки работают без CDN и интернет-соединения.
- Сгенерирован самостоятельный логотип RO-FACTORY; установлен в header и как favicon.
- Реализовано переключение разделов без перезагрузки страницы.
- Сохранено подключение интерфейса к существующим API производства.

### Разделы приложения

| Раздел | Возможности |
| --- | --- |
| Мой кабинет | Сводка показателей и возможности в зависимости от роли |
| Главная | Карта завода, выбор участка, показатели цеха и рекомендации |
| Производство | Состояние участков, линейный график выпуска, план/факт последней смены, события и узкие места |
| Оборудование | Сводка загрузки и оборудование из журнала простоев |
| Аварии | Таблица простоев: дата, оборудование, причина, длительность и критичность |
| Аналитика | Динамика выпуска и месячный план по моделям |
| ИИ Анализ | Рекомендации по качеству и простоям, предупреждения и события |
| Внести смену | Единая форма для выпуска, качества и простоя; доступна администратору |

Над разделами находятся общие фильтры по датам и участку. Кнопка «Скачать CSV» выгружает отфильтрованные записи выпуска, качества и простоев. Раздел оборудования содержит реестр, даты ТО, состояние и накопленные простои; администратор может создавать и редактировать карточки.

На главной предусмотрено состояние «цех не выбран». Нажатие на участок открывает его показатели. Состояние выбранного участка сохраняется при переключении разделов в рамках открытой страницы.

### Графики и показатели

- Столбчатый график заменён линейным SVG-графиком с сеткой, точками и подсказками.
- Добавлены периоды: весь доступный период, последние 7 и 30 дней относительно последней записи в данных.
- В производстве график отображает выпуск сборки; на главной — выпуск выбранного участка.
- Добавлены полосы «План / факт» для участков последней смены.
- Добавлены карточки узких мест по отклонениям участков.
- Сохранены месячный план по моделям, предложение увеличения плана и применение предложения администратором.
- Фильтры периода и участка применяются к KPI, карте, графикам, спискам записей и рекомендациям.
- CSV-отчёт открывается в Excel и учитывает текущие фильтры.
- Результат симуляции сравнивает ключевые KPI с предыдущей сменой и сохраняется в журнале событий.

### Авторизация и роли

- Добавлена страница входа `/login` с показом/скрытием пароля и сообщениями об ошибках.
- Добавлены кабинеты администратора и пользователя.
- В header добавлено меню по нажатию на имя или аватар: **«Мой кабинет», «Профиль», «Выйти»**.
- В профиле можно изменить имя и пароль.
- Администратор может создавать аккаунты с ролями `admin` и `user`, блокировать, активировать и удалять чужие аккаунты. Последнего активного администратора удалить или заблокировать нельзя.
- Заблокированный аккаунт не может войти; его сессии завершаются.
- Удаление собственного аккаунта из кабинета запрещено.
- Свой аккаунт нельзя заблокировать из кабинета администратора.

| Действие | Пользователь | Администратор |
| --- | --- | --- |
| Просматривать показатели, графики и рекомендации | Да | Да |
| Редактировать своё имя и пароль | Да | Да |
| Создавать и блокировать аккаунты | Нет | Да |
| Изменять производственные записи и месячный план | Нет | Да |
| Запускать и сбрасывать симуляцию | Нет | Да |
| Открывать документацию API `/docs` | Нет | Да |

Права проверяются сервером. Скрытие кнопок в интерфейсе дополнительно отражает доступные действия.

### Хранение паролей и сессий

- Пароли хранятся как PBKDF2-SHA256 хеши с индивидуальной солью и 600 000 итераций.
- В cookie хранится случайный токен сессии; в базе — его SHA-256 хеш.
- Cookie имеет атрибуты `HttpOnly` и `SameSite=Strict`. Сессия действует 8 часов.
- Для запросов, изменяющих данные, проверяется CSRF-токен; также проверяется Origin при его наличии.
- Добавлено ограничение попыток входа: 10 для одного логина и 50 для одного IP за 15 минут.
- Выход отзывает текущую сессию. Смена пароля завершает остальные сессии аккаунта.

### Мобильная версия

- До 1023 px боковая навигация открывается кнопкой-бургером в header.
- Меню закрывается после выбора раздела, кнопкой закрытия, нажатием на фон или Escape.
- В открытом меню фокус клавиатуры остаётся внутри панели; прокрутка основного экрана блокируется.
- Header закреплён сверху на телефонах и планшетах.
- На телефонах KPI расположены над основным контентом; на узких экранах — в две колонки.
- Формы перестраиваются в одну колонку; графики подстраиваются под ширину карточки.
- Широкие таблицы прокручиваются внутри карточек, не расширяя всю страницу.
- На компьютере сохранено постоянное боковое меню.

## Установка и первый запуск

Требуется Python 3.10 или новее. Все команды выполняются из папки проекта.

### 1. Окружение и зависимости

```bash
python -m venv .venv
```

Активация в Windows CMD:

```bat
.venv\Scripts\activate
```

Активация в macOS/Linux:

```bash
source .venv/bin/activate
```

Установка зависимостей:

```bash
pip install -r requirements.txt
```

### 2. Создание первого администратора

```bash
python manage_users.py create-admin
```

Команда запросит логин, имя, пароль и его повтор. Пароль должен содержать 12–128 символов. Символы пароля при вводе в терминале не отображаются.

**Встроенных логинов и паролей нет.** Остальных пользователей можно создать через кабинет администратора.

### 3. Запуск сервера

```bash
python -m uvicorn main:app --reload
```

Откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/). До входа приложение перенаправит на страницу авторизации. После входа откроется кабинет соответствующей роли.

HTML-файлы нельзя запускать отдельно через `file://`: приложению нужен сервер FastAPI.

### Управление аккаунтами из терминала

Создание пользователя:

```bash
python manage_users.py create-user
```

Сброс пароля существующего аккаунта:

```bash
python manage_users.py reset-password
```

Сброс пароля через терминал завершает все сессии этого аккаунта.

## База данных

По умолчанию используется `factory.db` в текущей папке. Другой путь задаётся переменной окружения `DATABASE_PATH`. При запуске создаются недостающие таблицы; начальные данные производства добавляются, если таблица производственных записей пуста.

| Таблица | Данные |
| --- | --- |
| `line_runs` | Производственные линии: план, факт, время работы и загрузка |
| `downtimes` | Простои оборудования |
| `production_plans` | Месячный план по моделям |
| `quality_records` | Выпуск и брак по участкам |
| `event_log` | Журнал событий |
| `auth_users` | Логин, имя, хеш пароля, роль, статус и дата создания аккаунта |
| `auth_sessions` | Хеши токенов сессий, CSRF-токены и срок действия |
| `auth_login_attempts` | Попытки входа для ограничения перебора |
| `equipment_assets` | Реестр оборудования, состояние и даты техобслуживания |

**При обновлении оставляйте свою `factory.db` на месте.** Не заменяйте её файлом из ZIP: в ней находятся ваши пользователи и производственные данные. Новые таблицы оборудования и авторизации создаются автоматически при запуске.

База с аккаунтами, `.env`, виртуальное окружение и временные файлы не должны попадать в новые коммиты. Если `factory.db` уже отслеживается Git, `.gitignore` не исключит её автоматически: добавляйте в коммит конкретные файлы кода.

## API

`/health` и страница входа доступны без авторизации. Производственные API требуют действующую сессию. Изменение производственных данных доступно только администратору.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | Проверка доступности сервера |
| GET, POST | `/api/lines` | Производственные записи |
| GET, POST | `/api/downtimes` | Простои оборудования |
| GET, POST | `/api/quality` | Производство и брак |
| GET, POST | `/api/plans` | Планы по моделям |
| PUT, DELETE | `/api/plans/{plan_id}` | Изменение и удаление плана |
| GET | `/api/dashboard` | KPI и предупреждения |
| GET | `/api/alerts` | Предупреждения |
| GET | `/api/production-flow` | Последовательность производственных участков |
| POST | `/api/shift-entry` | Запись смены: выпуск, качество и простой одной операцией |
| GET, POST | `/api/equipment` | Просмотр и создание карточек оборудования |
| PUT | `/api/equipment/{asset_id}` | Изменение карточки и графика ТО |
| GET | `/api/reports.csv` | Выгрузка CSV по выбранному периоду и участку |
| GET | `/api/factory-state` | Состояния участков последней смены |
| GET | `/api/recommendations` | Рекомендации по отклонениям |
| GET | `/api/plan-recommendation` | Предложение изменения месячного плана |
| GET | `/api/events` | Журнал событий |
| POST | `/api/event-note` | Добавление события администратором |
| POST | `/api/simulation/shift` | Симуляция смены |
| POST | `/api/simulation/reset` | Возврат демонстрационных производственных данных |
| POST | `/api/auth/login` | Вход |
| GET | `/api/auth/me` | Текущий пользователь и CSRF-токен |
| POST | `/api/auth/logout` | Выход |
| PATCH | `/api/auth/profile` | Изменение своего имени |
| POST | `/api/auth/password` | Смена своего пароля |
| GET, POST | `/api/admin/users` | Список и создание аккаунтов |
| PATCH, DELETE | `/api/admin/users/{user_id}` | Блокировка, активация или безопасное удаление аккаунта |

Для линий, простоев, качества, KPI, карты, оборудования и рекомендаций доступны параметры `start_date`, `end_date` и `area` там, где они предусмотрены маршрутом. Даты передаются в ISO-формате `YYYY-MM-DD`; участок — `Сварка`, `Окраска` или `Сборка`.

Для изменяющих запросов из авторизованного клиента нужен заголовок `X-CSRF-Token`, полученный при входе или через `/api/auth/me`. Фронтенд добавляет его автоматически.

Документация API: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs). Доступна после входа администратором. OpenAPI: `/openapi.json`.

## Симуляция и ограничения данных

Администратору доступны три сценария смены: штатная работа, сбой оборудования и рост брака. Симуляция добавляет записи и обновляет показатели. Сброс возвращает демонстрационные производственные данные и не удаляет аккаунты.

Интерфейс отображает доступные данные API:

- В модели есть три участка: сварка, окраска и сборка. Штамповка из макета отсутствует в данных.
- Графики показывают выпуск по дням; почасовые значения API не предоставляет.
- Правые KPI рассчитываются за весь доступный период. Производство указывается в автомобилях, а не в автомобилях/час.
- Качество отображается как `100% − доля брака`.
- OEE является оценкой: средняя загрузка × ограниченное 100% выполнение плана × доля годной продукции. Нормативного времени цикла для классического расчёта OEE нет.
- Список оборудования строится из журнала простоев и не является полным реестром оборудования.
- Температура, вибрация, очереди, здоровье оборудования и прогноз риска не предоставляются текущим API. Их значения не выдумываются.
- «ИИ Анализ» отображает рекомендации на основе правил и порогов бэкенда; отдельная модель машинного обучения не подключена.

Подробный сценарий демонстрации исходного кейса — в [DEMO_SCRIPT.md](DEMO_SCRIPT.md). В текущей версии перед демонстрацией требуется вход администратором.

## Проверка выполненных изменений

В ходе разработки выполнены:

- проверки синтаксиса Python и JavaScript;
- HTTP-тесты входа, ролей, CSRF, профиля, смены пароля, блокировки, выхода, отзыва сессий и ограничения попыток входа;
- браузерные сценарии Chromium с реальным FastAPI и отдельной тестовой базой: вход администратора, создание пользователя, изменение профиля, выход, вход пользователя и смена пароля;
- проверки обоих кабинетов и разделов на ширинах 320, 360, 390, 414, 768, 1024 и 1350 px;
- проверки бургера, закрытия по фону и Escape, фокуса клавиатуры, изменения размера окна и отсутствия горизонтального переполнения страницы.

Тестовые аккаунты не включены в поставляемую базу. Эти проверки выполнены в среде разработки; отдельный автоматизированный набор тестов в репозиторий не добавлен.

## Настройки для размещения на сервере

Для HTTPS включите `AUTH_COOKIE_SECURE=1` в окружении сервера. Для локального HTTP значение по умолчанию — `0`. За обратным прокси настройте корректную передачу схемы HTTPS и заголовка Host.

`--reload` используется для разработки. При размещении на сервере запускайте приложение без этого параметра.
